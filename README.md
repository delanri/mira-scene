# Mira — 雨夜咖啡馆

一个移动端优先的实时互动场景。暴雨后的深夜，你透过咖啡馆的玻璃窗，遇见一个刚拍完雨景、想找人说说话的旅行摄影师 Mira。你可以打字或按住说话和她聊天：她会用语音回答并显示字幕，表情和动作会跟着对话变化，场景也会因为对话出现闪电、灯光闪烁、雨变大。聊到摄影，她会伸手拿起桌上的相机，把她说的那张照片给你看：照片按她说的内容实时生成，像拍立得一样慢慢显影出来。

不是聊天列表，画面主体就是场景和角色。

## 快速开始

```bash
pip install -r requirements.txt
python server.py
```

浏览器打开 `http://localhost:5000`（推荐 Chrome 或 Edge）。观测页在 `http://localhost:5000/debug`。

- **不需要任何 API key**：没有配置时自动进入**演示模式**，所有交互、动作、场景事件、失败降级都能完整体验，照片用内置的冰岛极光
- 想用真实模型：`cp .env.example .env`，填入 `DEEPSEEK_API_KEY`，重启即进入**在线模式**
- 想让照片按内容生成：在 `.env` 里配置本地 ComfyUI 或智谱 CogView（见下文「照片生成」）
- 页面右下角显示当前模式：`演示` / `在线` / `离线`（在线但模型失败，本轮降级为演示回复）
- 所有前端依赖都在仓库里（Vue 3.4.38 放在 `static/js/`），打开页面不需要访问任何 CDN，也不需要构建

用 Docker 也可以一条命令启动：

```bash
docker compose up
```

### 测试和类型检查

```bash
python -m unittest   # 后端 36 个测试（不需要任何 key，外部服务全部 mock）
node --test          # 前端 22 个测试（Node 18+，在 Node 里跑真实的前端模块）
npm install && npm run typecheck   # 可选：TypeScript 检查前端 JSDoc 类型（不改变运行方式）
```

## 功能一览

| 题目要求 | 实现 |
|---|---|
| 场景为主，不是消息列表 | 透过玻璃看咖啡馆：窗框、玻璃水珠、雨、暖光、桌上的咖啡和相机，SVG 角色 Mira |
| 角色状态 | 待机 / 倾听 / 思考 / 说话，状态栏文字 + 角色动画（思考轻微摇摆、说话口型和轻微起伏） |
| 文字和语音互动 | 文字输入；按住麦克风说话（Web Speech API） |
| 语音回复 + 字幕 | 浏览器语音合成，字幕跟随语音进度逐字出现，说完后被"雨水冲刷"淡出 |
| 语音打断 | 说话时按住麦克风或直接发文字，立即停声、取消未完成的回复 |
| 结构化角色/场景指令 | `emotion` / `action` / `scene_change` / `photo` JSON，见下文 |
| 情绪 ≥3 种 | 6 种：neutral / curious / happy / melancholy / surprised / shy（害羞会脸红） |
| 非说话动作 ≥2 种 | 6 种：lean_forward / look_away / show_photo / sip_coffee / touch_hair_clip / hand_to_mouth |
| 背景/环境变化 ≥1 | 暴雨加强、闪电、灯光闪烁 |
| 由对话触发的视觉事件 | 聊到摄影或旅行：她伸手握住桌上的相机举起来，说完给你看照片 |
| **多模态** | **按她正在说的内容生成照片**（本地 ComfyUI 工作流 / 智谱 CogView-3-Flash）。生成期间拍立得显示"她在翻相机…"并像显影一样出现；失败、超时退回内置照片。另有 SVG + CSS 的角色动画 |
| 前后端闭环 + 失败恢复 | 超时、断网、模型失败、生图失败、语音识别失败都有反馈和恢复方式，见下文 |
| 无需私人 key | 演示模式 |

额外做了：好感度三阶段（状态栏 ✦✦✦ 显示）、对话上下文、生图缓存、观测页、自动化测试、Docker。

```
│ index.html  场景 + 内联 SVG 角色       │          │ server.py                             │
│ style.css   所有动画（CSS 驱动）        │  JSON    │  POST /api/chat                       │
│ js/（ES 模块，不需要构建）             │ ───────▶ │   ├ 轮数 → 好感度阶段                 │
│  main.js      入口：把浏览器能力交进去  │          │   ├ 演示：mock_data 关键词            │
│  mira.js      组装各模块                │ ◀─────── │   ├ 在线：DeepSeek（JSON，坏了重试） │
│  chat.js      一轮对话 / 打断 / 重试    │          │   │   失败 → 演示回复 + fallback      │
│  character.js 表情 / 动作 / 场景        │          │   ├ 规范化：拿相机 ⇔ 照片事件         │

│  speech.js    她说话（TTS）             │  轮询    │  GET  /api/photo/<id>  生成进度       │
│  listen.js    按住说话（STT）           │ ───────▶ │  POST /api/event       前端事件       │
│  photo.js     照片：进度 / 显影 / 退回  │          │  GET  /debug           观测页         │
│  events.js    事件上报                  │          │ imagegen.py  ComfyUI / 智谱，缓存     │
└────────────────────────────────────────┘          │ store.py     SQLite（任务/对话/事件） │
                                                     └───────────────────────────────────────┘
```

| 文件 | 作用 |
|---|---|
| `server.py` | Flask 服务、Mira 人设 prompt、DeepSeek 调用（格式坏了重试一次）与降级、好感度、指令规范化、观测页 |
| `imagegen.py` | 照片生成：ComfyUI（提交工作流 → 轮询 → 取图）和智谱 CogView 两种来源，按描述缓存，后台线程跑 |
| `store.py` | SQLite（Python 自带）：生图任务状态、每轮对话、前端事件 |
| `mock_data.py` | 演示模式：关键词 → 预设回复（带优先级、英文整词匹配、按好感度解锁的版本） |
| `comfyui/mira_photo_api.json` | ComfyUI 工作流（API 格式，SDXL 文生图），`%PROMPT%` 处填入照片描述 |
| `static/index.html` | 场景结构和内联 SVG 角色（相机也在 SVG 里，和手同一坐标系） |
| `static/css/style.css` | 所有视觉和动画：情绪、动作、场景事件、照片显影、字幕淡出 |
| `static/js/*.js` | 前端模块（见上图），JSDoc 写类型，`tsc` 检查 |
| `tests/` | 后端 unittest + 前端 node:test |

**角色的表现完全由 CSS class 驱动**：前端把 `currentEmotion`、`currentAction`、`characterState` 作为 class 加到角色容器上，`style.css` 决定每个 class 下眼睛、嘴、手、发夹、相机怎么动。加一个新动作只需要加一组 CSS + 在 prompt 里登记。

**前端模块不直接碰浏览器全局对象**：Vue、fetch、语音识别、语音合成都由 `main.js` 通过 `createMiraApp(env)` 传进去。测试时换成假的，每个测试一套，互不干扰；浏览器里直接跑原文件，不需要打包。

## 语音交互与打断流程

```
按住麦克风 → 倾听（在听…）→ 松手 → 识别出文字 → 发送
                                                   │
发送 → 思考（等她想一下）→ 回复到达 → 说话：语音 + 字幕 + 情绪/动作/场景
                                          │
                       说话中按住麦克风 / 发文字 = 打断
```

**打断时发生的事（`chat.js` 的 `interruptSpeech()`）**

1. 立即停止语音（`speechSynthesis.cancel()` / 停止音频）
2. 停止字幕打字，历史里把她这句改成「已经说出的部分……（被打断）」，模型下一轮知道自己没说完
3. 生成新的 `requestId`，旧回复在之后任何一步（拿到回复、准备语音、开始播放）检查到 id 过期就直接丢弃
4. 动作收回（举着相机的话先放回桌上再收手），还没给你看的照片不再弹出
5. 按麦克风打断 → 切换到倾听；发文字打断 → 直接进入思考，处理新输入

**思考中按麦克风**：正在路上的请求会被 `AbortController` 取消，迟到的回复不会盖掉「在听…」。

**为什么用"按住说话"而不是自动语音检测**

- 角色的语音从扬声器放出来，自动检测在没有回声消除时会把她自己的声音当成用户开口，导致自己打断自己
- Web Speech API 没有可控的语音活动检测和回声消除
- 按住说话在手机上是熟悉的交互（类似语音消息），打断意图明确，不会误触发
- 文字输入同样可以随时打断，没有麦克风也能完整体验

## 角色和场景指令

模型（或演示模式）每轮返回：

```json
{
  "text": "要看吗？上个月在冰岛拍的——黑沙滩上的北极光。",
  "emotion": "happy",
  "action": "show_photo",
  "scene_change": { "type": "event", "value": "show_photo" },
  "photo": {
    "prompt": "Aurora borealis over a black sand beach in Iceland at night, ...",
    "caption": "冰岛，上个月 —— 黑沙滩上的北极光"
  }
}
```

后端再附加：`mode`（mock / live / fallback）、`affinity`（1–3）、`request_id`，并把 `photo` 换成生成任务 `{job_id, caption}`。

| 字段 | 取值 | 画面 |
|---|---|---|
| `emotion` | neutral / curious / happy / melancholy / surprised / shy | 眼睛大小、嘴型、发夹、腮红；切换时先眨眼，眼型变化藏在闭眼里 |
| `action` | lean_forward / look_away / show_photo / sip_coffee / touch_hair_clip / hand_to_mouth | 手和道具的动作，3 秒后自动收回（相机除外，说完话才放下） |
| `scene_change` | `background: rain_heavy`、`effect: lightning`、`event: lights_flicker / show_photo` | 雨变大、闪电、灯光闪烁、照片 |
| `photo` | 只在 `show_photo` 时：英文画面描述 + 中文配字 | 按描述生成照片 |

**视觉事件和对话绑定，不靠定时器**

- 照片在她说完这句话之后才出现，内容就是她刚才说的那张
- 后端规范化：模型只给了"拿相机"没给"照片"（或反过来）时自动补齐；模型忘了给照片描述时，用她说的话凑一个，保证照片和台词对得上
- prompt 里约束 scene_change 只在有冲击力的时刻用（情感揭露 → 闪电，对话变深 → 雨变大）

**好感度**：按轮数分三段，写进每轮的 prompt：

| 阶段 | 轮数 | 她的态度 |
|---|---|---|
| 初识 ✦ | 1–3 | 只是想找人说话，不好奇你是谁 |
| 好奇 ✦✦ | 4–6 | 注意到你问的东西不一样，开始反问你 |
| 熟络 ✦✦✦ | 7+ | 主动问你的事；被问在等谁时说真话；害羞但不再躲 |

演示模式同样生效：例如问"你在等谁"，前 6 轮她会躲开（单手掩嘴），第 7 轮以后会说真话（脸红、往前凑）。

## 照片生成（多模态）

```
回复到达（带 photo 描述）→ 后端开任务，记进 SQLite（queued → running → done / failed）
     │                         └ 同样的描述生成过 → 直接用缓存
     ├ 她开始说话，前端每秒查一次进度（她说话这几秒刚好用来生成）
     └ 她说完 → 拍立得弹出
          ├ 已生成：照片从暗、模糊、偏黄慢慢显影
          ├ 还在生成：显示"她在翻相机…"，好了再显影
          └ 失败 / 超过 30 秒 / 图片打不开：退回内置的冰岛极光，记一条事件到观测页
```

两种来源，在 `.env` 里配置（都不配就用内置照片）：

| 来源 | 配置 | 说明 |
|---|---|---|
| 本地 ComfyUI | `COMFYUI_URL=http://127.0.0.1:8188`、`COMFYUI_CHECKPOINT=你的模型文件名` | 后端把 `comfyui/mira_photo_api.json` 的 `%PROMPT%` 换成照片描述、随机种子，`POST /prompt` 提交，轮询 `/history/<id>`，从 `/view` 取图。换自己的工作流只要在提示词节点里写 `%PROMPT%`；Turbo / Lightning 类模型可用 `COMFYUI_STEPS` / `COMFYUI_CFG` 覆盖采样参数 |
| 智谱 CogView-3-Flash | `ZHIPU_API_KEY=...` | 同步接口，生成后立刻下载到本地（链接会过期） |

两个都配置时优先用本地 ComfyUI；也可以用 `IMAGE_PROVIDER=comfyui / zhipu / none` 指定。生成的图片存在 `static/generated/`，生成记录在 `data/mira.db`。

实测（观测页数据）：本地 ComfyUI（Comfy Desktop v0.42.5 + SDXL 1.0 + RTX 5070）约 8 秒一张，智谱 CogView-3-Flash 约 12 秒一张，都在她说话的那几秒里基本完成。

Comfy Desktop 的端口不一定是 8188，以 ComfyUI 设置里的服务器端口为准；模型名要和 ComfyUI「Load Checkpoint」节点下拉框里显示的一字不差。

## 失败和降级

| 情况 | 用户看到的 | 恢复方式 |
|---|---|---|
| 断网 / 服务器错误 | Mira："……雨声太大了，刚才没听清。你再说一遍？" | 字幕里「再说一次」按钮，原句重发 |
| 20 秒没有回应 | Mira："……抱歉，刚刚走神了。你能再说一遍吗？" | 同上 |
| 模型返回的 JSON 坏了或缺台词 | 后端立刻再要一次，用户无感 | 两次都失败才按下一行降级 |
| 模型出错、超时、重试仍失败 | 她照常回话（演示回复），右下角变为橙色「离线」 | 下一轮自动重试在线模型 |
| 照片生成失败 / 超时 / 打不开 | 拍立得里显示内置的冰岛照片 | 下次同样的描述会重新生成 |
| 语音识别没听到声音 | Mira："……嗯？你刚刚说什么了吗？" | 再按住说一次 |
| 麦克风没有权限 / 浏览器不支持语音识别 | 输入框上方提示用文字 | 改用文字 |
| 没有语音合成 | 字幕照常按语速出现 | — |

失败的提示用角色的口吻说，不弹系统错误框，不打断场景氛围。失败的那句话不会留在对话历史里，重发时只发一次。

## 观测页（/debug）

每 5 秒自动刷新，数据都在 SQLite 里：

- 汇总：对话轮数、平均 / 最慢后端耗时、降级次数、格式坏了重试次数、打断次数、前端超时 / 断网、生图成功 / 失败 / 缓存、生图平均耗时
- 最近 30 轮对话：模式、好感度、耗时、模型调用次数、双方内容、情绪动作、错误
- 前端事件：打断、重试、超时、断网、语音识别失败、照片退回（这些只有前端知道，由前端上报 `/api/event`）
- 生图任务：来源、状态、耗时、描述、配字、缩略图、错误

## 模型、媒体和第三方服务

| 用途 | 方案 |
|---|---|
| 对话 | DeepSeek Chat（`deepseek-chat`），JSON 输出模式 |
| 照片生成 | 本地 ComfyUI（SDXL 工作流）或智谱 CogView-3-Flash |
| 语音识别 | 浏览器 Web Speech API（Chrome / Edge） |
| 语音合成 | 浏览器 SpeechSynthesis（`zh-CN`） |
| 前端框架 | Vue 3.4.38（本地文件，MIT），无构建步骤 |
| 后端 | Flask、python-dotenv、requests；SQLite（Python 自带） |
| 角色和场景素材 | 全部为手写 SVG / CSS，无外部图片素材 |

## 关键技术选择与取舍

- **SVG + CSS 角色，而不是 Live2D / Spine**：不需要美术资源和运行时，任意分辨率清晰，每个部件都能单独做动画，体积很小。代价是表现力有限，复杂动作要手算坐标。一个具体的坑：手是 SVG、相机原本是 HTML，两个坐标系在不同屏幕宽度下对不齐，最后把相机也画进 SVG 解决
- **照片放在"拿相机"这个时刻生成**：生图要几秒，正好用她说话的时间来生成；拍立得的"显影"让等待变成表演的一部分，而不是一个加载圈。失败时有内置照片兜底，场景不会断
- **生图做成可换来源的任务**：ComfyUI 和云端接口用同一套任务状态、缓存和失败处理，前端只关心 `queued / running / done / failed`。换模型或换工作流不用改前端
- **浏览器语音（STT / TTS），而不是云端语音服务**：零成本、零 key、延迟低，演示模式也能完整说话。代价是声音质量取决于系统，Chrome 的语音识别依赖谷歌服务
- **无构建步骤，但不放弃结构和类型**：前端拆成按职责划分的 ES 模块，浏览器原生加载；类型写在 JSDoc 里，用 `tsc` 检查。`git clone` 后两条命令就能跑，同时保留了模块化和类型检查。正式上线时会换成 TypeScript + 构建工具
- **薄后端**：后端只负责藏 key、拼 prompt、降级、规范化指令和生图任务，对话状态都在前端。打断、过期回复丢弃都在前端用 requestId 完成
- **历史按完整 JSON 发回模型**：她以前说的话连同情绪、动作一起发回给模型，而不是只发台词。只发台词时，聊到第三轮左右模型就开始漏字段、JSON 格式坏掉
- **模型自由选动作 + 后端规范化**：让模型按语境选动作更自然，但模型不稳定，所以在后端补齐"拿相机 ⇔ 照片"这类必须成对的指令，而不是在 prompt 里反复强调
- **SQLite 而不是外部数据库**：生图任务、对话记录、事件量都很小，Python 自带的 SQLite 零配置、零依赖，面试官本地直接能跑
- **好感度按轮数而不是按内容**：确定、可预期、能测试，3–5 分钟的体验刚好走完三个阶段。代价是不会因为聊得好而更快熟起来
- **演示模式关键词匹配**：先比关键词长度，一样长再比优先级（话题 > 情绪 > 招呼），英文按整词匹配，避免"你的相机好看"被"好看"抢走

## 已知问题

- Chrome 的语音识别需要访问谷歌服务，部分网络环境下不可用（会提示改用文字），可以换用 Edge
- 浏览器不报告逐词进度的声音，字幕节奏是按语速估算的（中文约 220ms/字，可在 `static/js/config.js` 调整）
- 智谱 CogView 生成的照片右下角带"AI生成"水印（平台默认加的，关闭需要和智谱签免责协议），本地 ComfyUI 生成的没有
- 生成的照片每次都可能长得不一样，同一个地点在不同轮里不保证一致（同样的描述会命中缓存）
- ComfyUI 工作流默认是 SDXL 文生图，需要在 `.env` 里写上本地的模型文件名；生成的图片不会自动清理
- `scene_change` 一次只能有一个，后端补"照片"事件时会顶掉同一轮的其他场景变化
- 放下相机的动画还没播完时，如果新回复带着用左手的动作，手会直接跳过去
- 演示模式下"你好，外面雨好大"会匹配到打招呼（"你好"比"雨"长）

## 如果继续开发两周

1. **降低延迟**：模型流式输出 + 按句切分送语音，第一句话更快出声；在观测页展示首包延迟
2. **照片的连续性**：用固定的风格和参考图生成，让她在不同轮里拍的同一个地方看起来是同一个地方；关键剧情节点生成短视频
3. **更准的字幕和口型**：换成带时间戳的云端语音，字幕和嘴型逐字对齐
4. **自动语音检测 + 回声消除**：在有回声消除的前提下支持直接开口打断，区分"嗯""对"这类附和
5. **好感度结合内容**：根据对话内容和情绪调整，不只看轮数
6. **工程化**：前端迁移到 TypeScript + Vite，生图任务换成队列（多用户时排队、限流、重试），会话回放
7. **端到端测试**：用 Playwright 在真实浏览器里跑完整对话流程
